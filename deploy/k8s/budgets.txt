# 로컬 k3d 플랫폼 메모리 예산 (TASK-36#2·#7, B1). 단위 MiB. scripts/_k3d.sh 의 사전 검사와 README(로컬 k8s)가 이 파일 하나를 쓴다.
# 형식: <키> <값> <설명...>
#   docker-min            Docker VM 메모리(docker info MemTotal) 최소. Docker Desktop 5GB 설정의 실측은 약 4.8GiB(커널 예약),
#                         4GB 설정은 약 3.8GiB 라 그 사이(4.5GiB)를 경계로 둔다.
#   limit                 켠 프로필 예산 합계의 상한. 5GB VM − k3s 서버·Traefik·CoreDNS·local-path·LB·레지스트리(약 0.9GiB)
#                         − 이미지 빌드(buildkit)·여유(약 0.9GiB). 넘으면 k3d-up·k3d-profile·k3d-smoke 가 실패한다(FORCE=1 만 통과).
#   profile <이름> <MiB>  프로필의 메모리 한도 합계: Deployment·StatefulSet 컨테이너 limits × replicas + Job 컨테이너 limits.
#                         k8s_test.sh 가 매니페스트에서 다시 계산해 이 값 이하인지 확인한다. 프로필을 추가하면 이 줄과
#                         deploy/k8s/profiles/<이름>/ 을 같이 만든다. 여기에 없는 프로필은 켤 수 없다.
#   vm-min                Rocky 개발 VM(rocky-dev) 메모리(/proc/meminfo MemTotal) 최소(TASK-64#4). 5GB(5120MiB) VM 의 실측은
#                         MemTotal 4649MiB(커널 예약 — Rocky 9.8 커널 실측)라 4608 은 여유가 41MiB 뿐이다. 커널·펌웨어 예약이 조금만 늘어도
#                         실패하지 않게 4500(여유 약 150MiB). 4GB VM(약 3.7GiB)은 확실히 걸린다. 미만이면 맥의 make test·k3d 진입점이 실패한다(scripts/_vm.sh).
#   sonar                 SonarQube(TASK-67#2) 기동 전 VM 사용 가능 메모리(MemAvailable) 최소. 미만이면 make sonar-up 이 실패한다(B1, scripts/_sonar.sh).
#                         실측 RSS(sonar-rss) + 분석(make sonar-scan: gradle test·Testcontainers·스캐너) 여유.
#   sonar-rss             SonarQube + DB 컨테이너 실측 메모리 합(make sonar-status, 힙 web·ce·search 384m). 2026-10-29 기동 직후 실측:
#                         sonarqube 1807MB(web 약 720·search 약 700·ce 약 230 MiB RSS) + db 129MB ≈ 1.9GiB → 2000. 안내 기준값
#   mac-free-min          맥 여유 메모리(vm_stat free+inactive+speculative) 경고 기준. VM 을 켠 8GB 맥에서 이보다 적으면 스왑으로 느려진다.

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. (AC#1 FE-34) app/error.tsx·global-error.tsx·not-found.tsx 를 만든다. error/global-error 는 클라이언트 컴포넌트로 한국어 안내 + '다시 시도'(Next 16 의 retry, 없으면 reset) 버튼, 원문 error.message 는 화면에 보이지 않고 console.error 로만 남긴다(TASK-28 B2). global-error 는 자체 <html lang=ko>/<body>. not-found 는 한국어 + 목록(/) 링크. 테스트(vitest) 먼저, next build 로 out/404.html 생성을 확인한다.
2. (AC#2 FE-35, B1) CloudFront Function 하나를 기본 동작의 viewer-request·viewer-response 에 함께 건다. 페이지 경로 목록(app 의 page.tsx 에서 나오는 9개)을 함수에 두고, 목록에 없는 확장자 없는/슬래시 경로는 viewer-request 에서 /404.html 로 바꾸고 viewer-response 에서 상태를 404 로 바꾼다. /api/*·/uploads/* 는 함수 안에서도 건드리지 않는다(이중 방어). custom_error_response 는 배포 전체(/api 포함)에 걸리므로 계속 쓰지 않는다. 테스트: scripts/test/cf_function_test.mjs(요청·응답 핸들러, /api·/uploads 미변경, 경로 목록 = app 의 page.tsx 목록 일치 검사), frontend_cdn.tftest.hcl(기본 동작 viewer-response 연결, /api/*·/uploads/* 함수 없음, custom_error_response 없음).
3. (AC#3 FE-36) ui/alert.tsx 의 기본 role 을 variant 로 나눈다(destructive=alert, default=status, role prop 으로 덮어쓰기 가능). 기본 variant 사용처(오프라인 배너, 초안 복원, 재조회 실패 안내, 정지 경고, 계정 안내)를 의미대로 status 로 두고, 오류(세션 만료·폼 오류·API 오류 등)는 alert 를 유지한다. 편집기(제목·본문·카테고리·태그·첨부)와 댓글 입력의 오류 문단에 id 를 주고 입력에 aria-describedby + aria-invalid 를 연결한다. 테스트 먼저.
4. docs/frontend.md·README(CDN 동작) 갱신, make test·tsc·eslint·next build 확인.
